# AGENTS.md
This file provides guidance to coding agents when working with code in this repository.

## Project Overview

Pure Swift library for demangling (and remangling) Swift mangled symbols. Port of the Swift compiler's `Demangler` / `Remangler` / `NodePrinter` to idiomatic Swift, targeting reverse-engineering tooling.

- **Library target**: `Demangling`
- **Swift tools version**: 6.2 (strict concurrency)
- **Platforms**: macOS 10.15+, iOS 13+, macCatalyst 13+, tvOS 13+, watchOS 6+, visionOS 1+
- **Dependency**: `FrameworkToolbox` (provides `FoundationToolbox`, `SwiftStdlibToolbox`)

## Build & Test

```bash
swift package update && swift build 2>&1 | xcsift
swift package update && swift test 2>&1 | xcsift
```

Run a single test by name:
```bash
swift test --filter DemanglingTests.NodeBuilderTests/initWithExistingNode
```

Tests use the Swift Testing framework (`@Suite`, `@Test`, `#expect`, `Issue.record`), **not** XCTest.

## Architecture

### Core Pipeline

```
mangled string → Demangler → Node tree → NodePrinter → human-readable string
                                       → Remangler  → re-mangled string
                                       → TypeDecoder → abstract type (via TypeBuilder)
```

### Key Types

- **`Node`** (`Node.swift`) — Immutable tree node (reference type, `Sendable`). Uses a unified `Payload` enum that merges contents (`.text`/`.index`/`.none`) and children (`.oneChild`/`.twoChildren`/`.manyChildren`) into a single discriminated union — contents and children are mutually exclusive. Mutation methods are `fileprivate`; external code must use `NodeBuilder`.
- **`Node.Children`** (`Node.Children.swift`) — Inline storage for 0–2 children without heap allocation; falls back to `ContiguousArray` for 3+.
- **`NodeBuilder`** (`Node.swift`) — Thread-safe builder for constructing `Node` trees incrementally (the node under construction lives in a `SwiftStdlibToolbox.Mutex`, so the type is plain `Sendable`). Every node it hands out is frozen: `node` returns a detached snapshot, `build()` detaches from the returned node (the builder remains usable; later mutations affect only later builds), and `init(_:)` seeds a shallow copy in O(1). This is what makes cyclic `Node` graphs unconstructible from public API — do not reintroduce a path that exposes the live instance the builder mutates.
- **`Node.create()`** (`Node+Init.swift`) — Public static factories that go through `NodeCache.shared` for leaf-node interning. Always use these instead of `Node.init()` when creating nodes that should be cached. The `@_spi(Internals)` `Node.createTransient(...)` counterparts never touch the cache — use them (together with `demangleAsNodeTransient`, which also accepts a `symbolicReferenceResolver`) in pipelines that must not pin anything in global state, such as symbolic-reference resolvers and store-feeding bulk demangling.
- **`NodeCache` / `NodeFactory`** (`NodeFactory.swift`) — `NodeCache` is the global interning cache with two levels: leaf nodes are interned eagerly at creation time, and whole trees are hash-consed bottom-up via `intern(_:)` / `internTreeUnsafe(_:)` (structurally equal subtrees collapse to one shared instance; interior-node keys compare children by `===`, which is safe because children are canonicalized before their parent; the walk additionally memoizes canonical results by source-instance identity for its own duration, because the `===`-keyed probe alone misses every repeated instance whose children were replaced — without the memo, interning a shared DAG cost the path count, 2^N, straight through default `demangleAsNode` — evolution 0006). `demangleAsNode` runs the tree-interning pass by default (`internsSubtrees: true`), so identical symbols demangle to the identical (`===`) tree; opt out with `internsSubtrees: false`. `NodeFactory` provides pre-created singletons for common parameterless nodes (e.g., `NodeFactory.emptyList`, `.asyncAnnotation`). The `Node.init(...)` convenience initializers in `NodeFactory.swift` are **internal** and bypass the cache — they exist for `Demangler`/`Remangler` internals.
- **`Node.Kind`** (`Node+Kind.swift`) — Exhaustive enum of ~300 node kinds matching the Swift compiler's `Demangle::Node::Kind`.
- **`Demangler`** (`Demangler.swift`) — Byte-based scanner over the input's UTF-8 (proposal 0008): `~Escapable` over a `Span<UInt8>`, so a demangle runs entirely inside the borrow scope opened in `DemangleInterface.swift` and only the `Node` tree escapes. Generic over `WordRangeStorage` (the word-substitution table): the entry instantiates `Demangler<InlineWordRanges>` (stack-resident `InlineArray`) on macOS 26-family runtimes and `Demangler<ArrayWordRanges>` on the legacy path. Text materialization is fixed per entry by `TextMaterializationStrategy`: known-ASCII inputs (`UTF8Span.isKnownASCII`) skip UTF-8 revalidation via `String(copying: UTF8Span(unchecked:))`; everything else decodes with validation — the ASCII gate is load-bearing, because a byte subrange of non-ASCII UTF-8 can split a scalar. `DemanglingRuntimePath.forcesLegacyPath` (`@_spi(Internals)`, or env `DEMANGLING_FORCE_LEGACY_PATH=1`) forces the legacy path so one modern machine covers both paths (`DualPathParityTests` + CI double-run). Error offsets in `DemanglingError` are byte offsets. Parses mangled prefixes `_T0`, `_$S`, `_$s`, `$S`, `$s`, `$e`, `_$e`, `@__swiftmacro_`. The `Demangling` target enables the `Lifetimes` experimental feature package-wide — storing `Span` in the scanner requires it, so the compiler floor is a Lifetimes-capable toolchain (Apple toolchains from tools 6.2 on).
- **`Remangler`** (`Remangler.swift`) — Converts a `Node` tree back to a mangled string. Uses hash-based substitution merging.
- **`NodePrinter<Target>`** (`NodePrinter.swift`) — Generic over `NodePrinterTarget` protocol. Converts a `Node` tree to human-readable output controlled by `DemangleOptions`.
- **`DemangleOptions`** (`DemangleOptions.swift`) — `OptionSet` with presets: `.default`, `.simplified`, `.interface`, `.interfaceType`, etc.
- **`TypeDecoder<Builder>`** (`TypeDecoder.swift`) — Walks a `Node` tree and builds abstract types via the `TypeBuilder` protocol.
- **`Node.Rewriter`** (`Node+Rewriter.swift`) — Open class for bottom-up tree rewriting. Override `visit(_:)` to transform nodes. `visit` runs **once per unique node instance** (results are memoized and reused at every occurrence of a shared subtree), so it must be a pure transformation of its input.
- **Traversal** (`Store/DemanglingNode+Sequence.swift`, `Node+Sequence.swift`) — the traversal machinery (`preorder`/`inorder`/`postorder`/`levelorder`), the kind-lookup helpers (`first(of:)`, `all(of:)`, `contains(_:)`, `filter(of:)` on `Sequence where Element: DemanglingNode`), and `identifier` are single generic implementations shared by both representations; `Node` and `NodeReference` each conform to `Sequence` with preorder as the default. Do not re-add `Node`-specific copies. **Short-circuit queries are deduped; enumerating ones are not, and that split is deliberate.** `first(of:)` / `contains(_:)` over a whole subtree resolve to overloads on `DemanglingNode where Self: Sequence, Self.Element == Self` that run one identity-deduped preorder pass (`printCacheIdentity` as the key, shared helper `firstNodeInDedupedPreorder`); `identifier` does the same. Dedup is sound for them because a repeat visit of a shared instance cannot contain anything its first visit did not, so "first match in preorder" and "is there one" are unchanged — while the walk costs node count instead of path count (measured before: 18.2s on a 22-level doubling DAG, ×4 per two levels, and a *fruitless* query — the common case — pays it in full since there is nothing to short-circuit on; evolution 0007). `all(of:)`, `filter(of:)` and the `preorder()` family stay path-based: they enumerate the logical tree, where occurrence counts are the correct answer (`KnownIssues.md` N6). **Note the bypass**: writing `node.preorder().first(of:)` explicitly gets the `Sequence` overload and is path-priced again — query the node directly. Value queries added later should follow the deduped pattern, not raw `for child in self` over a whole subtree.
- **`NodeStore` / `NodeStoreBuilder` / `NodeReference`** (`Store/`) — Arena-based compact storage for bulk demangling (evolution proposal 0001; design notes and measurements in `Documentations/NodeStoreArena.md`). Nodes are flat 12-byte `CompactNode` values referenced by `UInt32` indices in one contiguous buffer; the `~Copyable` builder hash-conses on insert and `consuming freeze()` produces an immutable `Sendable` store. Interning tables are open-addressing slot arrays holding 4-byte indices (keys recovered from the buffers — no separate key storage). When the symbol count is known up front (bulk indexing), call `reserveCapacity(expectedSymbolCount:)` first: it pre-sizes the three flat buffers and the three interning tables from corpus-measured per-symbol coefficients (proposal 0009), removing ~a dozen full-buffer regrowth copies per buffer and their transient old+new memory spikes; `capacityUtilization` reports used/reserved per buffer for re-calibrating the coefficients, and `freeze()` deliberately does not shrink. Debug builds stamp every minted `NodeIndex` with its builder's issuance tag (random-seeded monotonic `UInt16`) and verify it in `reference(at:)` and `intern(kind:children:)`, so a cross-builder/cross-store index — which in release silently resolves in-range to an unrelated subtree — traps deterministically during development (proposal 0009; release layout and behavior are unchanged, the tag field compiles out). The builder's `demangle(_:)` bridge is fully cache-free (Phase 3): the transient tree is built with `internsLeaves: false`, so nothing touches `NodeCache.shared`; it forwards a `symbolicReferenceResolver`, since bulk indexing of metadata mangled names is exactly where symbolic references occur. `intern(kind:...)` overloads construct nodes directly in the arena (wrapper `.type` nodes for index keys, etc.). `NodeReference` is a 16-byte value handle mirroring `Node` accessors (kind/text/index/children), plus borrowed text views (proposal 0008 B1: closure-style `withTextUTF8` as the all-platform baseline, `@_spi(Internals)` direct-return `textUTF8Span()` dual-gated on `hasFeature(Lifetimes)` AND the macOS 26 runtime, and the legacy `textUTF8` `ArraySlice` kept for source stability — each slice access pays a retain/release the borrowed forms avoid), allocation-free `isIdentifier`/`isSwiftModule` witnesses, `structurallyEquals(_ node: Node)` (zero-materialization cross-representation structural equality — the bridge for finding an externally demangled `Node` among `NodeReference` dictionary keys, since the frozen store drops its intern tables; text compares by **exact UTF-8 bytes**, deliberately stricter than `Node.==`'s canonical equivalence, because byte-level interning can hold NFC and NFD spellings as two indices and a canonical bridge would break transitivity), `structurallyEquals(_ other: NodeReference)` (same-store O(1) via index equality, cross-store structural walk) plus `structuralHash(into:)` (structure-consistent hashing for value types that key dictionaries by node structure while storing references — `NodeReference`'s intrinsic `Hashable` is store-identity based. **This is not a deduplication defect — it has been reported as one in review, and the finding does not hold**: the builder hash-conses on insert, so within one arena "same index" *is* "same structure" and `Set`/`Dictionary` deduplicate normally (pinned by `hashedCollectionsDeduplicateWithinOneArena`) — up to text *spelling*, since text interns by exact UTF-8 bytes, so NFC and NFD spellings of one identifier are two indices in one arena, deliberately (that byte exactness is what keeps the cross-representation bridge transitive, and demangled input does not produce two spellings on its own); only references from *different* arenas compare unequal, which is why the structural pair exists, and making `==` itself structural would replace a pointer-and-integer compare with a two-tree walk on every bucket probe in a type that exists to be a 16-byte handle. A `Set` that fails to deduplicate means one arena per element — the shape `NodeReference(interning:)` produces per call, so it is the wrong tool for a batch (measured: 300 references over 3 unique symbols → 300 entries / 59,700 bytes private, versus 3 entries / 541 bytes in one shared arena); both it and `Node.hash(into:)` combine one bottom-up **memoized structural digest**, so hashing a maximally shared DAG costs its node count, not its path count — the structural-equality walks carry the same proven-pair memo), `NodeReference(interning:)` (interns one `Node` tree into a fresh private mini store — self-contained handles for values that outlive their source tree), and a `CustomStringConvertible` debug dump (materialization bridge). `demangleAsNodeTransient` is exported via `@_spi(Internals)` for bulk indexers that classify on the transient tree before interning it (the returned tree is NOT canonical — and not instance-distinct either: parameterless kinds are process-wide `NodeFactory` singletons and substitution back-references share instances, so never key per-occurrence logic by `ObjectIdentifier`/`===` on it). `materialize()` rebuilds a standalone (non-`NodeCache`) `Node` tree with an index-keyed memo, so store-level subtree sharing survives as shared instances instead of expanding the DAG.
- **`DemanglingNode` / generic engines** (`Store/DemanglingNode.swift`, `Node/Printer/NodePrinter.swift`, `Main/TypeDecoder/TypeDecoder.swift`) — read-only tree protocol conformed by both `Node` and `NodeReference` (members named to match `Node`'s API so generic engine bodies are representation-agnostic). Engines: `DemanglingPrinter<Target, SomeNode>` behind the public `NodePrinter<Target>` facade (store printing reads straight from the arena, byte-identical to the `Node` path across the full dyld-cache corpus; `NodeReference.print` instantiates the engine on the internal `UnretainedNodeReference` handle — an `Unmanaged` store accessed only through `_withUnsafeGuaranteedRef` plus a raw index, the swift-syntax `RawSyntaxArenaRef` layering; `unowned(unsafe)` storage was tried first and still cost one compiler-inserted retain/release per store method call — inside a `withExtendedLifetime`/strong-capture anchor, so the walk pays zero store retain/release per visited child (proposal 0008 B2); handles never escape the walk, rich targets receive `materializedNode` products only), and `TypeDecoderEngine<Builder, SomeNode>` behind `TypeDecoder<Builder>` (the public `TypeBuilder` protocol still receives concrete `Node` at the five handoff points via `materializedNode`). **Printing is static-only**: `NodePrinter<Target>.print(_:using:)` and the SPI `DemanglingPrinter.print(_:options:)` are the only public ways to run the walk — both route through `StackSafeExecutor`, and the instance-level `printRoot` is internal so no consumer can tie a tree's surviving depth to its calling thread's remaining stack. The `Remangler` deliberately stays a `Node` engine — its walk constructs transient helper nodes with shared substitution state (same design as the C++ remangler) — so `mangleAsString(some DemanglingNode)` bridges through `materializedNode`. The derived helpers (`isSimpleType`, `needSpaceBeforeType`, `hasChildren`, `subscript(throwChild:)`, `isIdentifier(desired:)`, `isSwiftModule`, `isKind(of:)`, and `second` on `DemanglingNodeChildren`) live **only** on the `DemanglingNode` protocol/extension — do not re-add copies on `Node` or `Node.Children`: the generic engines dispatch to the shared implementation, so a parallel concrete copy would silently drift. `NodePrintContext.node` stays a concrete `Node?` and is populated on both paths via `materializedNode` (free for `Node`). Both rich-target hooks deliver their payload lazily: `NodePrinterTarget.pushTypeReferenceScope` takes its node as `@autoclosure () -> Node?` and `write(_:context:)` takes its context as `@autoclosure () -> NodePrintContext?` — targets that ignore them (`String`) never evaluate the closures, keeping store-backed plain-text printing materialization-free, while rich targets (e.g. `SemanticString`) evaluate them and receive `materializedNode`, materializing only the delivered subtree. **Neither hook has a default implementation, deliberately**: forwarding defaults used to absorb implementations written against the earlier eager signatures (`Node?` / `NodePrintContext?`) — the near-miss was not a witness, the default took its place, text output stayed byte-identical and every event vanished with no diagnostic, which no output-comparison test can catch. Without the defaults that same near-miss is a conformance error at the definition site. Every target therefore spells both methods out, including plain-text ones (`String`'s conformance is the reference shape to copy); `popTypeReferenceScope()` keeps its default because it takes no argument and so has no near-miss to absorb. Note the delivered node is canonical **only on the `Node` path**: store-backed printing builds a fresh non-interned subtree per evaluation, so two pushes of the same store index are not `===`. Rich targets must key scopes by structure (e.g. the remangled string, as `SemanticString` does) — never by `ObjectIdentifier`/`===`. `DemanglingPrinter` and `StackSafeExecutor` are exported via `@_spi(Internals)` for deep consumers (MachOSwiftSection rich targets).
- **Stack safety / `StackSafeExecutor`** (`Utils/`) — the model mirrors the Swift project's own (design notes, upstream evidence and measurements in `Documentations/StackSafety.md`; proposal 0002 records a briefly shipped remaining-stack-bytes design and why it was reverted): the three engines carry **fixed depth limits, and they are upstream's**, while `StackSafeExecutor` moves work onto a large-stack thread when the calling thread runs low. The limits are `DemanglingPrinter.maxPrintDepth = 768`, `Remangler.maxDepth = 1024` (reachable at all only because `hashForNode` ↔ `entryForNode` is iterative — the recursion sat outside `mangle(_:depth:)`'s counter and overflowed first, upstream has the identical hole), and `TypeDecoderEngine.maxDepth = 1024`. **Do not lower these without corpus evidence from downstream workloads.** They were briefly cut to 512/384/160 on this branch, calibrated against unoptimized-build overflow measurements (printer 725 levels survived / 745 overflowed an 8MB thread; remangler depth 565/605; decoder ~250, its frames being ~30KB per depth unit) on the premise that the deepest real symbol is 41 levels. That premise was wrong: downstream consumers reported `<<too complex>>` on ordinary SwiftUI-class modules under the 512 printer limit, so all three went back to upstream's (KnownIssues N8 records the reversal). The debug-build stack risk those cuts addressed is real and unsolved — at 768 an unoptimized build can exhaust an 8MB thread before the counter fires — but it is tracked as a stack-safety problem (KnownIssues #4), not paid for by truncating output a release build renders fine. `StackSafeExecutor.execute` runs inline when the caller has ≥ 2MB of stack remaining (the main thread, consumer-created big threads, LLDB expression evaluation) and otherwise hops to a **bounded pool of long-lived 8MB-stack workers**. Pool properties that are load-bearing: workers never retire; a worker is created before its work is queued and creation is checked (`pthread_create`, never `Thread.start()`, which reports nothing); when concurrent submitters all fail to spawn, the last roll-back **drains the queue on its own thread** before refusing — without that, a submitter that saw another's phantom reservation queues an item nobody will ever run and blocks forever (reproduced in `LargeStackThreadPoolTests`); `trySubmit` can refuse, in which case the caller gets a dedicated one-off 8MB thread, or runs inline as the last resort; a worker never submits back into its own pool (nested calls either have stack to spare and run inline, or get a dedicated thread). Growth: steady-state `max(2, activeProcessorCount)`; blocking submissions may grow it to `max(32, 4 × that)` to break fan-out wait cycles; async submissions stay under steady state. `withLargeStack(_:)` is the batch-boundary entry — wrap an indexing pass and every call inside runs inline. **`TypeDecoder` deliberately does NOT route through the executor**: its `TypeBuilder` callbacks are user code that may be actor-isolated or thread-bound, so they always run on the calling thread; deep batches wrap themselves in `withLargeStack`. `Node.description` also runs inline — its dump is iterative and cannot overflow, and it is what a debugger's `po` evaluates. **Adding a new recursion**: it must either converge on a depth-checked entry point or be iterative; verify with the call-graph audit described in `Documentations/StackSafety.md` (build the SCCs, delete the candidate convergence point, re-run) — a single check on `mangle` was never enough, six cycles bypassed it. Whole-tree walks outside the engines are iterative because no entry-point guard can reach them: `NodeCache.internTreeUnsafe`, `NodeStoreBuilder.internTree`, `Node.==` / `hash(into:)`, `Node.copy()` / `replacingDescendant(_:with:)` (public, and `NodeBuilder` runs them while holding its lock), `Node.Rewriter.rewrite` (`final`; only `visit` is `open`), `Node.description`'s dump, `NodeStore.materializeNode`, `NodeReference.structurallyEquals` / `structuralHash`, `getUnspecialized`, and the `.type`-unwrapping predicates `DemanglingNode.isSimpleType` / `needSpaceBeforeType` and `Node.isProtocol` (bounded loops sharing `maxTypeWrapperUnwrapDepth = 64`; `isProtocol` was the last one still recursing). All three are public, so their input may be caller-assembled rather than demangler-produced, and none sits inside an engine's stack guard; past the limit they answer the conservative `false` instead of overflowing, which is unreachable on demangled input because the demangler never nests `.type` (longest consecutive run across the corpus is one). The bound doubles as defense-in-depth against cycles, which are no longer constructible from public API since `NodeBuilder` hands out only frozen detached nodes. These walks are also **memoized by instance identity** where they rebuild or emit per node — `copy()` / `replacingDescendant` / `Rewriter.rewrite` rebuild a shared subtree once and reuse it (`visit` runs once per unique instance and must be a pure transformation), and `Node.sharedStructureDescription` (`@_spi(Internals)`) expands a multiply-referenced interior subtree once, labeling it `(shared #N)` and printing `(see #N)` at later occurrences — because interning and substitution back-references make demangled trees DAGs, and an unmemoized rebuild costs the path count (a real 48-unique-node symbol expanded to 131,070 visits), not the node count. The pairwise structural-equality walks carry a lazily created proven-pair memo for the same reason — `Node.==`, both `NodeReference.structurallyEquals` overloads, and the remangler's `SubstitutionEntry.deepEquals` (the substitution-table equality; it was the last of the four without one, and a signature holding two instance-distinct copies of a shared bound-generic subtree made `mangleAsString` exponential in the sharing depth — evolution 0005). The canonicalization and annotation walks carry the same per-walk identity memo — `NodeCache.internTree` (its `SubtreeKey` probe only short-cuts while the probed node's own children are already canonical) and the demangler's `setParentForOpaqueReturnTypeNodes` post-pass (which runs on every plain-function symbol, so without the memo even `internsSubtrees: false` demangling was exponential in a crafted symbol's sharing depth) — and the value queries `Node.findGenericParamsDepth()` / `DemanglingNode.identifier` run one identity-deduped pass instead of path-based scans (all four: evolution 0006). `TypeDecoder` remains per-occurrence: deduplicating it changes when `TypeBuilder` callbacks fire, a contract decision tracked as KnownIssues #6, not a mechanical fix. **`description` itself is deliberately not memoized**: its format is compared byte for byte against the Swift runtime's node dump by the corpus conformance oracle (`DemanglingTestingSupport/DemanglingTests.swift`), so it expands every occurrence like the runtime does, and a pathological DAG is bounded by an 8MB output budget instead — past it the dump stops and says `... (truncated: …)`. The budget never fires in practice: across the full 4.5M-symbol corpus the largest expanded dump is 496,018 bytes, and eliding instead cost 1,433,597 oracle mismatches (31.7% of the corpus). `Sequence` traversals (`preorder()` et al., `all(of:)`) deliberately stay path-based: they enumerate the logical tree, where occurrence counts are the correct answer. `Node.deinit` tears trees down with an explicit work list because releasing a deep tree recurses in the runtime where no engine guard can reach it. **Still recursive and deliberately so**: `Demangler`'s `setParentForOpaqueReturnTypeNodesImpl` (now memoized by source identity — evolution 0006 — but still recursive in depth) / `demangleBoundGenericArgs` and the `demangleSwift3*` recursive-descent component (reachable only through the `_T` prefix; upstream's `OldDemangler` carries a `MaxDepth` counter this port does not — decided not to port it, the prefix is effectively extinct). Non-Darwin platforms have no executor; the depth limits alone are the guard, same as before.
- **`Demangler` construction seam** (`Main/Demangle/Demangler+NodeCreation.swift`) — every node the demangler builds goes through `createNode(...)` instance methods; `internsLeaves: false` (used by the internal `demangleAsNodeTransient`) bypasses `NodeCache.shared` entirely. New construction sites in `Demangler` must use `createNode(...)`, never `Node.create(...)` directly.

### Node Identity vs Equality

`Node` is a reference type with structural `Hashable` conformance: `==` compares kind + contents + children recursively, while `===` checks identity. Interned nodes from `NodeCache` guarantee identity equality for structurally equal trees: leaves are canonical from creation, and any tree returned by `demangleAsNode` (default `internsSubtrees: true`) is fully canonical, so structurally equal subtrees are the same instance across all demangled symbols.

### Public API Entry Points

```swift
// Demangle
func demangleAsNode(_ mangled: String, isType: Bool = false, ...) throws(DemanglingError) -> Node

// Print — sync and async variants live on the DemanglingNode extension (single
// implementation for Node and NodeReference); the async one suspends instead of
// blocking a cooperative worker when the walk hops to a large-stack thread.
node.print(using: .default)      // → String (human-readable)
await node.print(using: .default) // → same output; for callers on the Swift concurrency pool
node.description                  // → debug tree dump (kind=..., text=...); every occurrence expanded, byte-identical to the Swift runtime's dump; bounded at 8MB
node.sharedStructureDescription   // → @_spi(Internals) same dump priced by graph size: shared interior subtrees print once, labeled "(shared #N)"/"(see #N)"

// Remangle — also the serialization path: `Node` is deliberately NOT `Codable`.
// A mangled symbol already is the serialized form of a tree: smaller than any
// node encoding, stable across releases, sharing-preserving through the round
// trip, and the format the rest of the toolchain speaks. Persist the string.
// (`Node.Children` is not `Codable` either — it holds `Node`. `Node.Contents`
// and `Node.Kind` keep theirs; they stand on their own.)
func mangleAsString(_ node: Node, usePunycode: Bool = true) throws(ManglingError) -> String
func canMangle(_ node: Node) -> Bool

// Helpers
"$s...".isSwiftSymbol             // prefix check
"$s...".stripManglePrefix         // remove mangling prefix
```

## Conventions

- Swift 6 strict concurrency. **Shared mutable state goes in a `SwiftStdlibToolbox.Mutex`, not behind a hand-rolled lock plus `@unchecked Sendable`** — `NodeBuilder` and `NodeCache` both hold their state in one, so both are plain `Sendable` and the unsafety is reviewed once inside `Mutex` instead of at every entry point. Two deliberate exceptions remain: `LargeStackThreadPool` keeps `NSCondition` because workers must *wait* on a condition variable and a mutex cannot express that, and `Node.payload` is `nonisolated(unsafe)` because `deinit` has to write it for the iterative teardown (both carry the reasoning at the declaration). When a `Mutex`-held value is only reachable from one isolation domain, `withLockUnchecked` avoids `sending` constraints that buy nothing.
- Typed throws throughout: `throws(DemanglingError)`, `throws(ManglingError)`, `throws(TypeLookupError)`.
- **Never spell a bound check as `Int(UInt32.max)`** (or `Int(UInt64.max)` / `Int(UInt.max)`): the package ships for watchOS, where `Int` is 32 bits and that conversion overflows at constant-folding time — the compiler silently reduces the enclosing function to an unconditional trap while the build stays green. Compare heterogeneously instead (`count <= UInt32.max`), the same idiom as stdlib `KeyPath` and swift-syntax. Enforced by `DefectRegressionTests.librarySourceAvoidsWordSizeDependentIntegerConversions`; background in `Evolutions/0004-32bit-store-guards.md`.
- Performance-sensitive code is marked `@inlinable` / `@usableFromInline`.
- Use `Node.create()` (not `Node.init()`) when creating nodes that should participate in leaf interning. Direct `Node.init()` is for internal demangler/remangler use only.
- Test pattern: demangle with `demangleAsNode()`, print with `.print(using: .default.union(.synthesizeSugarOnTypes))`, assert with `#expect`.
